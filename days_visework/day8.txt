3. app/main.py (updated)
   - Registered the new requests router

HOW IT WORKS
------------

- POST /requests creates a request tied to whoever is logged in (via their
  JWT token) - the user cannot set user_id manually, it comes from auth.
- New requests always start with status = "pending".
- instance_type, estimated_cost, and security_score are left empty (null)
  at creation time - these get filled in later by the Day 26-28
  recommendation, cost estimation, and security validation modules.
- GET /requests returns only the logged-in user's own requests, UNLESS
  they are an admin, in which case it returns everyone's requests
  (this is what the Day 16 admin dashboard will use).
- GET /requests/{id} blocks a regular user from viewing someone else's
  request (403 Forbidden), but allows admins to view any request.

PROBLEMS ENCOUNTERED AND FIXED
---------------------------------

1. File saved with incorrect capitalization (Routes_requests.py instead of
   routes_requests.py) caused an import error, since Python's import
   statement used the lowercase name.
   Fix: Renamed the file to lowercase using Rename-Item.

2. A stray, unrelated virtual environment (.venv) one level above the
   project folder kept getting activated by accident instead of the
   correct one (backend\venv), causing "module not found" errors even
   though the packages were correctly installed elsewhere.
   Fix: Permanently deleted the stray .venv folder so it can no longer be
   activated by mistake; standardized on backend\venv going forward.

3. VS Code's editor showed "import could not be resolved" warnings because
   its selected Python interpreter did not match the project's venv.
   Fix: Manually pointed VS Code to
   D:\cloud resourse provider protal\backend\venv\Scripts\python.exe
   via "Python: Select Interpreter" > "Enter interpreter path".

4. Briefly tested the wrong endpoint (GET /requests instead of POST
   /requests) since both appear close together on the Swagger page.
   Fix: Located the green POST /requests ("Create Request") entry
   specifically, as opposed to the blue GET one.
